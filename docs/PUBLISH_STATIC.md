# Публикация статического starter-а

## Самый простой путь: GitHub Pages

В проекте уже есть `.github/workflows/pages.yml`. Он проверяет проект, собирает папку `dist` и публикует её.

1. Создай пустой репозиторий на GitHub.
2. Загрузи в корень репозитория все файлы starter-а, включая скрытую папку `.github`.
3. Открой `Settings → Pages`.
4. В `Build and deployment` выбери `Source: GitHub Actions`.
5. Открой вкладку `Actions` и дождись зелёной проверки `Publish AIRC starter to GitHub Pages`.
6. Ссылка появится в настройках Pages и в отчёте workflow.

При каждом новом коммите в `main` сайт будет обновляться автоматически.

## Проверка перед отправкой

```bash
npm run doctor
npm run check
npm run build
```

В `dist` лежит готовый статический сайт. Маршруты используют `#`, поэтому внутренние экраны открываются на обычном статическом хостинге без серверной настройки маршрутов.

## Другой хостинг

Папку `dist` можно разместить в Object Storage, на российском статическом хостинге или другом сервисе. Для production с базой и персональными данными статической публикации недостаточно: нужен серверный API и подходящая инфраструктура. Смотри `RF_PRODUCTION.md`.

## Ручной smoke-test

После публикации открой ссылку:

- в инкогнито;
- с телефона через мобильный интернет;
- после очистки локальных данных;
- по каждому внутреннему маршруту;
- с неверным вводом в форме;
- после повторной загрузки страницы.

Проверь, что `runtime-config.js` не содержит секретов, а интерфейс честно сообщает, если данные остаются только в текущем браузере.
